# PPT-Web 簡報工作站：規劃與設計

> 狀態：M0、M1 完成；下一步 M2（備忘稿）
> 最後更新：2026-10-28

## 1. 目標

把做好的 PPT 丟進網頁，就能：

- 在電腦上瀏覽整份簡報（縮圖列 + 大圖，不能編輯），再全螢幕放映
- 用手機掃 QR Code，把手機變成簡報筆：上一頁、下一頁、黑幕
- 在手機上直接看備忘稿（講稿）
- 接投影機時，筆電可以開講者檢視：目前頁、下一頁、備忘稿、計時器
- 整個站是靜態網站，部署在 GitHub Pages，不用自架後端

**不做的事**

- 線上編輯簡報
- 帳號系統、雲端存放簡報
- 把簡報放進 repo 公開分享（簡報只在自己電腦上用）

## 2. 已確認的需求

| 問題 | 回答 | 對設計的影響 |
|---|---|---|
| 簡報要放上網站分享嗎？ | 只在自己電腦上用 | 只做本機載入；匯出工具也只輸出本機檔案 |
| 常用「逐項出現」動畫嗎？ | 會 | 需要處理動畫步驟，見 [§3.4](#34-動畫逐項出現) |
| 場地網路？ | 可以用手機網路 | 電腦連手機熱點最穩，TURN 維持選配 |
| 電腦端要講者檢視嗎？ | 要，完整一點的 PPT 檢視，不需要編輯 | 電腦端分成檢視、放映、講者檢視三種畫面 |

## 3. 核心難題與決策

### 3.1 在瀏覽器顯示 PPT

瀏覽器不能原生顯示 PPTX，有三條路：

| 方案 | 畫面還原度 | 備忘稿 | 使用門檻 |
|---|---|---|---|
| 前端直接渲染 PPTX（pptxjs 一類套件） | 差。字型、圖表、SmartArt 常跑版 | 有 | 最低 |
| **PDF 顯示畫面 + PPTX 取備忘稿（採用）** | 高。PDF 是 PowerPoint 自己輸出的，用 pdf.js 向量渲染 | 從 PPTX 解析 | 要多匯出一次 PDF |
| 匯出工具：PowerPoint COM 產生每個步驟的畫面 | 最高，而且保留動畫步驟 | 有 | 要跑工具，排在 M5 |

**決策**：先用 PDF 顯示畫面，PPTX 只用來讀備忘稿。動畫步驟見 §3.4。

### 3.2 手機跟電腦怎麼通訊

靜態網站沒有後端，所以用 **WebRTC DataChannel** 讓手機和電腦點對點直連，只在配對那一刻借用公共的 signaling 伺服器交換連線資訊。

- 用 **PeerJS**（它有免費的 PeerJS Cloud signaling），最成熟、範例最多
- 連線邏輯包在 `Transport` 介面後面，之後可以換成 Trystero（同時用多個公共 relay，沒有單點故障）或自架 PeerServer
- 不採用：Firebase / Supabase（要申請帳號和金鑰）、BroadcastChannel（只能在同一個瀏覽器內通訊）

**網路情境與風險**

| 情境 | 預期結果 |
|---|---|
| 電腦連手機熱點 | 穩定，**現場首選** |
| 手機和電腦連同一個 Wi-Fi | 穩定 |
| 手機用 4G，電腦用場地 Wi-Fi | 多半可以；遇到擋 UDP 的公司網路或對稱型 NAT 會連不上，需要 TURN 伺服器 |
| PeerJS Cloud 故障 | 無法配對。M6 加備援 transport |
| 完全沒網路 | 無法配對，但鍵盤和實體簡報筆照常可用 |

對策：開場前可以按「連線測試」；設定頁可以填自己的 TURN 伺服器（Cloudflare、Metered 都有免費額度）；斷線後自動重連。

### 3.3 從 PPTX 讀出備忘稿

PPTX 其實是 zip 檔，解開後用 XML 解析：

1. 投影片**順序**看 `ppt/presentation.xml` 的 `<p:sldIdLst>`。不能用檔名 `slide1.xml`、`slide2.xml` 排序，因為在 PowerPoint 裡拖動投影片順序時，檔名不會跟著改
2. 用 `ppt/_rels/presentation.xml.rels` 把 `r:id` 對到 `slides/slideN.xml`
3. `slideN.xml` 根節點有 `show="0"` 代表隱藏投影片
4. 在 `ppt/slides/_rels/slideN.xml.rels` 找 Type 結尾是 `/notesSlide` 的關聯，得到 `notesSlides/notesSlideM.xml`
5. 在 notesSlide 裡找有 `<p:ph type="body"/>` 的 shape，逐段 `<a:p>` 串起 `<a:t>`，`<a:br/>` 轉成換行，用 `lvl` 保留縮排層級
6. 順便抓每頁標題（`<p:ph type="title"/>` 或 `ctrTitle`），做成手機上的跳頁清單

**隱藏投影片的對齊**：PowerPoint 匯出 PDF 預設不含隱藏投影片（範例檔已驗證：8 張投影片匯出 7 頁），所以要比對頁數：

- PDF 頁數 = 可見投影片數 → 拿掉隱藏投影片的備忘稿
- PDF 頁數 = 全部投影片數 → 全部保留
- 都對不上 → 照順序對齊，並跳出警告請使用者確認

不支援舊版 `.ppt`，請先另存成 `.pptx`。

### 3.4 動畫（逐項出現）

PDF 只會留下每張投影片「動畫全部播完」的樣子。因為你常用逐項出現，要另外處理：

| 方案 | 做法 | 優點 | 缺點 |
|---|---|---|---|
| A. PPspliT | 免費的 PowerPoint 增益集，把每個動畫步驟拆成獨立投影片，再匯出 PDF 和拆好的 PPTX | 現在就能用，不用寫程式；段落逐項出現也處理得好 | 多一個手動步驟；頁碼以「步驟」計算；同一張投影片的備忘稿會重複出現 |
| B. 自製匯出工具 | `tools/export-deck.ps1` 用 PowerPoint COM 讀動畫順序，自動產生每個步驟的畫面，打包成一個 `.pptweb` 檔（圖片 + 備忘稿 + 步驟對應表） | 一個檔案拖進去就好；可以顯示「第 3 張 · 步驟 2/4」；備忘稿不重複 | 工作量大；段落逐項出現、離開效果要逐一處理 |

**建議**：先用 A 確認整個流程順手，M5 再做 B。

**資料模型已預留**：導覽以「頁」為單位，不假設一頁就是一張投影片。之後一張投影片對應多個步驟頁時，只要多一張「頁 → 投影片／步驟」的對應表，翻頁邏輯不用改。

## 4. 系統架構

```
┌─────── 電腦：投影端 index.html ───────┐              ┌──── 手機：遙控端 remote.html ────┐
│ 拖入 PPTX + PDF                        │              │ 上一頁 / 下一頁 / 黑幕            │
│  ├ pdf.js 渲染 → 檢視／放映畫面        │   WebRTC     │ 目前頁、下一頁縮圖               │
│  ├ 解析 PPTX → 備忘稿、標題            │◀──────────▶│ 備忘稿（可調字級）               │
│  └ 產生縮圖（JPEG，寬約 480px）        │ DataChannel  │ 計時器、時鐘                     │
│ ShowController：唯一的播放狀態來源     │              │ Wake Lock 讓螢幕不休眠           │
│ IndexedDB：最近開過的簡報              │              │                                  │
└───────────────┬────────────────────────┘              └──────────────────────────────────┘
                │ BroadcastChannel（同一台電腦）
┌───────────────┴────────────────────────┐
│ 觀眾視窗 present（拖到投影機全螢幕）   │   ← M4 講者檢視
└────────────────────────────────────────┘
```

設計原則：

- **檔案不上傳**。簡報只存在電腦上，手機只收到備忘稿文字和小縮圖
- **ShowController 是唯一的狀態來源**。手機、觀眾視窗都只送指令、只顯示狀態；重新連線後由它重送完整狀態
- **所有輸入走同一套指令**：鍵盤、實體簡報筆、滑鼠、手機都送 `Command`（`src/core/navigation.ts`）

## 5. 配對與通訊協定（M3）

**配對**

- 投影端產生隨機 `roomId`（16 bytes，base64url），當作 PeerJS 的 peer id
- QR Code 網址：`https://eric861129.github.io/PPT-Web/remote.html#r=<roomId>`。放在 `#` 後面，瀏覽器不會把它送到網站伺服器
- 允許多支手機同時連線（例如助理幫忙翻頁），所有手機畫面同步
- 投影端重新整理後沿用同一個 `roomId`（存在 sessionStorage），手機不必重掃；若 signaling 回報 id 仍被占用，就退避重試

**訊息格式（JSON）**

手機 → 投影端：`nav` 和 `blank` 直接對應 `Command`

| type | 欄位 | 說明 |
|---|---|---|
| `hello` | `v` | 協定版本 |
| `nav` | `id`, `action`: `next` / `prev` / `first` / `last` | 翻頁 |
| `goto` | `id`, `index` | 跳到指定頁 |
| `blank` | `id`, `mode`: `black` / `white` / `off` | 黑幕、白幕 |
| `ping` | | 心跳 |

投影端 → 手機

| type | 欄位 | 說明 |
|---|---|---|
| `deck` | `title`, `count`, `notes[]`, `titles[]` | 連線時送一次 |
| `thumb` | `index`, `jpeg`（ArrayBuffer） | 先送目前頁附近，再背景補齊 |
| `state` | `index`, `blank`, `startedAt` | 每次狀態變動都送 |
| `pong` | | 心跳回應 |

`id` 用來去重：斷線重送同一個指令時，投影片不會多跳一頁。

## 6. 畫面設計

### 6.1 電腦端

三種畫面：

- **開始頁**：拖放區、「怎麼匯出 PDF」說明（M4 加最近開過的簡報）
- **檢視模式**（M1 完成）：上方標題列與放映按鈕、左側縮圖列、中間大圖（M2 在大圖下方加備忘稿面板）。點縮圖跳頁，雙擊大圖從該頁放映
- **放映模式**（M1 完成）：全螢幕、投影片置中保持比例。滑鼠一動，左下角出現工具列（上一頁、頁碼、下一頁、黑幕、結束），2.5 秒不動就連同游標一起隱藏
- **講者檢視**（M4）：筆電畫面顯示目前頁、下一頁、備忘稿、計時器，另開一個觀眾視窗拖到投影機全螢幕。Chrome / Edge 可用 Window Management API 自動把觀眾視窗放到第二個螢幕

按鍵（照 PowerPoint 的習慣，多數實體簡報筆送的就是這些鍵）：

| 動作 | 按鍵 |
|---|---|
| 下一頁 | `→` `↓` `Space` `PageDown` `Enter` `N`、滑鼠點畫面、滾輪往下 |
| 上一頁 | `←` `↑` `PageUp` `Backspace` `P`、滾輪往上 |
| 從頭放映／從目前頁放映 | `F5` / `Shift` + `F5` |
| 結束放映 | `Esc` |
| 黑幕／白幕（再按一次取消） | `B` `.` / `W` `,` |
| 切換全螢幕 | `F` |
| 第一頁／最後一頁 | `Home` / `End` |
| 跳頁 | 數字 + `Enter`（2 秒沒按 Enter 就取消） |

細節：

- 黑幕或白幕時按翻頁，只會先回到畫面，不會跳頁（跟 PowerPoint 一樣）
- 滾輪一段連續滾動只翻一頁，避免觸控板慣性一口氣翻好幾頁
- 前後各 2 頁預先渲染，翻頁約 10ms，不會閃白

### 6.2 遙控端（手機，直式，M3）

```
┌─────────────────────────────┐
│ ● 已連線    5 / 24   12:34  │  連線燈、頁碼（點一下開跳頁清單）、計時器
├──────────────┬──────────────┤
│   目前頁     │   下一頁      │  縮圖
├──────────────┴──────────────┤
│ 備忘稿                A− A+ │
│ 這一頁先講市場規模，         │  大字、可捲動、左右滑動也能換頁
│ 再帶到我們的切入點……         │
│                             │
├─────────┬─────────┬─────────┤
│ ◀ 上一頁 │  ■ 黑幕  │ 下一頁 ▶ │  下一頁按鈕最大，拇指好按
└─────────┴─────────┴─────────┘
```

- 深色主題，在台上不刺眼
- 黑幕開著時，整個遙控端外框變紅，避免忘了關
- 字級設定存在 localStorage
- Screen Wake Lock 讓手機不自動鎖屏（iOS 16.4 以上支援）
- Android 按下時震動回饋（iOS Safari 不支援 `navigator.vibrate`）
- 橫拿手機時：縮圖在左、備忘稿在右

**網頁做不到的事**：拿不到手機音量鍵，所以沒辦法用音量鍵翻頁。

## 7. 技術選型

| 項目 | 選擇 | 理由 |
|---|---|---|
| 建置 | Vite 8 + TypeScript 7，不用框架 | 頁面不多、狀態單純 |
| PDF 渲染 | pdfjs-dist 6 | 業界標準 |
| 解壓 PPTX | fflate（M2） | 比 JSZip 小很多 |
| XML 解析 | 瀏覽器內建 DOMParser | 不用額外套件 |
| P2P 連線 | PeerJS（M3） | 最成熟、文件多 |
| QR Code | qrcode（M3） | |
| 本機儲存 | idb-keyval（M4） | 簡化 IndexedDB |
| 測試 | Vitest；範例簡報由 PowerPoint 產生 | |
| 部署 | GitHub Actions → GitHub Pages | |

pdf.js 的字碼表、標準字型、wasm 解碼器由 `scripts/copy-pdfjs-assets.mjs` 在 `dev` / `build` 前複製到 `public/pdfjs/`（不進版控）。

## 10. 測試計畫

- **單元測試**（`npm test`）：翻頁與黑幕規則、按鍵對應、檔案檢查；M2 起加 PPTX 解析
- **範例簡報**：`scripts/make-sample-deck.ps1` 用 PowerPoint 產生，刻意包含中英混排、多段縮排備忘稿、無備忘稿的頁、隱藏投影片、搬動過順序的投影片、逐項出現動畫
- **瀏覽器實測**：M1 用無頭 Edge 跑過完整流程（開檔、翻頁、縮圖、滾輪、放映、全螢幕、閒置隱藏、黑幕、結束、關閉再開），也在模擬 GitHub Pages 子路徑 `/PPT-Web/` 下跑過 build 產出
- **裝置**（M3 起）：手機 iPhone Safari、Android Chrome；電腦 Chrome、Edge
- **網路**（M3 起）：電腦連手機熱點、同一個 Wi-Fi、手機 4G 對電腦 Wi-Fi
- **情境**（M4 起）：手機鎖屏後解鎖自動重連；投影端重新整理後恢復；兩支手機同時操作
